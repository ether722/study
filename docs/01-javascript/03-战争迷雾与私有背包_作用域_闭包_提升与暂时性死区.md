## 战场核心世界观：从战争迷雾看 JavaScript 变量可见性

在 MOBA 游戏中，视野系统是决定胜负的基石：
1. **全局作用域（Global Scope）**：大地图公屏广播，所有人、所有防御塔和野怪都能看到的全局公告（例如全图暴击提示）。
2. **函数作用域（Function Scope）**：英雄自己的技能范围，只有英雄体内才看得到。
3. **块级作用域（Block Scope, `{}`）**：草丛与战争迷雾！你在草丛里插了个眼（`let` / `const`），草丛外面的人根本看不见；但草丛里的人却能看清外面世界的开阔视野！
4. **闭包（Closure）**：**英雄背包里的专属私有神装**！即使英雄离开了泉水（外层函数执行完毕出栈），他身上背包里的私有装备仍然被他紧紧揣着，外部任何人无法直接抢走，只能通过英雄授权的按键接口（暴露的方法）进行读写！

```
┌─────────────────────────────────────────────────────────────┐
│               召唤师峡谷：作用域视野链 (Scope Chain)              │
└─────────────────────────────────────────────────────────────┘
 全局作用域 (Global / Window / globalThis) 
  [地图主水晶、全图广播变量]
      ▲
      │ 向上沿作用域链搜索 (逐级向上找视野)
  外层函数作用域 (Outer Function Scope)
   [高地兵营、野区祭坛]
      ▲
      │ 
  内层块级/闭包作用域 (Inner Block / Closure)
   [英雄草丛视野、私有背包格子]
   (可以随意访问外层世界的任何数据；但外层世界休想直接窥探内部！)
```

## 第一战：作用域链（Scope Chain）与词法作用域（Lexical Scope）

JavaScript 采用的是**词法作用域（静态作用域）**。也就是说：**一个函数能访问哪些变量，完全取决于这个函数在代码文本里被写在什么地方，而不是它在运行阶段被谁调用！**

```javascript
const vision = "全图普通视野 (全局)";

function enemyBase() {
  const vision = "敌方泉水视野 (局部)";
  
  // 重点：scoutWard 在全局定义，还是在 enemyBase 内部定义？
  return function scoutWard() {
    console.log("插眼侦测结果:", vision);
  };
}

const ward = enemyBase();
const vision = "我方高地视野";
ward(); // 输出："敌方泉水视野 (局部)"
// 为什么？因为 scoutWard 出生在 enemyBase 的体内，其词法作用域早已在代码书写时焊死！
```

## 第二战：闭包（Closure）——私有装备背包与内存逃逸

### 2.1 闭包的物理定义
当一个内部函数引用了其外部函数的变量，并且该内部函数在外部函数执行完毕后仍然存活（比如作为返回值传出或挂载到了全局），**闭包就诞生了**。  
此时，外部函数的**执行上下文虽然从调用栈弹出了，但被引用的变量环境（Lexical Environment Record）被挪到了堆内存中常驻**，绝不被垃圾回收！

### 2.2 实战：打造无法被作弊篡改的“英雄金币与背包系统”

```javascript
function createHero(heroName) {
  // 私有变量：敌方和外部脚本绝对无法直接 window.gold = 99999 修改！
  let gold = 600;
  const inventory = [];

  return {
    getName: () => heroName,
    
    // 闭包接口 1：打野补刀获得金币
    farmCreep: (creepBounty) => {
      gold += creepBounty;
      console.log(`${heroName} 击杀小兵，当前金币: ${gold}`);
    },

    // 闭包接口 2：商场购物
    buyItem: (itemName, cost) => {
      if (gold >= cost) {
        gold -= cost;
        inventory.push(itemName);
        console.log(`${heroName} 成功购买 [${itemName}]，剩余金币: ${gold}`);
      } else {
        console.warn(`金币不足！购买 [${itemName}] 需要 ${cost}，当前仅有 ${gold}`);
      }
    },

    // 闭包接口 3：安全展示背包
    inspectBackpack: () => [...inventory] // 防御性浅拷贝，防止外部直接 push 伪造装备
  };
}

const invoker = createHero("祈求者卡尔");
invoker.farmCreep(45);
invoker.buyItem("点金手", 2200); // 拦截：金币不足
invoker.farmCreep(2000);
invoker.buyItem("点金手", 2200); // 购买成功！

console.log(invoker.gold); // undefined！外部黑客休想通过属性窥探或篡改金币！
```

### 2.3 经典面试死穴：循环中的 `var` 与闭包陷阱

```javascript
// ❌ 灾难代码：var 只有全局/函数作用域，所有定时器共享同一个 i
for (var i = 1; i <= 3; i++) {
  setTimeout(() => {
    console.log("倒计时结束，释放大招:", i);
  }, 100);
}
// 输出：
// 倒计时结束，释放大招: 4
// 倒计时结束，释放大招: 4
// 倒计时结束，释放大招: 4

// ✅ 现代解法：用 let 声明块级作用域（每次循环自动创建独立的词法环境）
for (let j = 1; j <= 3; j++) {
  setTimeout(() => {
    console.log("独立冷却倒计时完毕:", j);
  }, 100);
}
// 输出：1, 2, 3！
```

## 第三战：变量提升（Hoisting）的物理机制

在 V8 等引擎中，代码运行分为两个阶段：
1. **编译解析阶段（Creation Phase）**：扫描所有声明，为变量和函数在当前作用域分配内存槽位。
2. **执行阶段（Execution Phase）**：逐行执行代码并赋值。

### 3.1 函数声明 vs 变量声明的特权差异
- **函数声明（Function Declaration）**：特权满级，**声明与函数体定义整体提升到作用域顶部**（开局自带六神装，可以在声明前直接释放）。
- **`var` 变量声明**：仅**声明提升**，初始化值为 `undefined`，赋值停留在原地。
- **函数表达式（Function Expression）**：如果用 `var fn = function(){}`，只有变量名 `fn` 提升为 `undefined`，提前调用会直接爆出 `TypeError: fn is not a function`！

```javascript
castUltimate(); // 完美施法！输出："全屏雷击！"

function castUltimate() {
  console.log("全屏雷击！");
}

console.log(bkbDuration); // 输出：undefined（提升了声明，但还没执行赋值）
var bkbDuration = 9;

// useBKB(); // 💥 TypeError: useBKB is not a function
var useBKB = function() {
  console.log("魔法免疫");
};
```

## 第四战：暂时性死区（Temporal Dead Zone, TDZ）

很多初学者误以为：`let` 和 `const` 没有提升。  
**大错特错！`let` 和 `const` 同样会被引擎在编译阶段提前感知，但它们被施加了“暂时性死区封印”！**

### 4.1 TDZ 的致命惩罚：ReferenceError
在作用域顶部，到 `let / const` 声明语句真正被执行到的这段物理区域，被称为 **TDZ（暂时性死区）**。在这期间访问该变量，引擎会毫不留情地抛出 `ReferenceError: Cannot access '...' before initialization`！

```
┌────────────────────────────────────────────────────────┐
│ {                                                      │
│    // ── 暂时性死区 (TDZ) 禁区开始 ──                    │
│    // 只要在这个区域碰 heroName，直接暴毙！              │
│    console.log(typeof heroName); // 💥 ReferenceError! │
│    console.log(heroName);        // 💥 ReferenceError! │
│    // ── 暂时性死区 (TDZ) 禁区结束 ──                    │
│                                                        │
│    let heroName = "影魔"; // 变量完成初始化解封！        │
│    console.log(heroName); // 输出："影魔"              │
│ }                                                      │
└────────────────────────────────────────────────────────┘
```

> **警惕陷阱**：在 `var` 时代，`typeof undeclaredVar` 是绝对安全的（返回 `"undefined"`）；但在 `let/const` 的 TDZ 禁区内，连 `typeof` 也会触发死区报错！

## 第五战：立即执行函数（IIFE）——远古时代的沙盒封印

在 ES6 模块化（`import/export`）诞生前，为了防止几十个 JS 脚本里的全局变量互相打架（如覆写同一个全局变量导致基地暴毙），开发者普遍采用 **IIFE（Immediately Invoked Function Expression）** 打造独立沙盒：

```javascript
// 远古英雄独立沙盒
const TeamLiquid = (function() {
  // 私有战术密码
  const secretStrategy = "速推肉山大魔王";

  function executeStrategy() {
    console.log("启动暗号:", secretStrategy);
  }

  // 暴露对外的战队接口
  return {
    fight: executeStrategy
  };
})();

TeamLiquid.fight(); // 输出："启动暗号: 速推肉山大魔王"
console.log(TeamLiquid.secretStrategy); // undefined！沙盒之外绝无泄露！
```
