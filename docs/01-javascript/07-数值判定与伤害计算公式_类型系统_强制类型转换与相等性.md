## 第一战：值传递 vs 引用传递与自动装箱（Autoboxing）

### 1.1 技能数值拷贝（按值） vs 背包共享（按引用）

```javascript
// 1. 原始类型：完全独立的伤害数值副本
let baseDamage = 100;
let boostedDamage = baseDamage;
boostedDamage += 50;
console.log(baseDamage);    // 依然是 100！不受任何外界影响！
console.log(boostedDamage); // 150

// 2. 引用类型：共享同一个背包指针！
const teamInventory = { wardCount: 2 };
const supportInventory = teamInventory; // 拷贝的是堆内存指针地址
supportInventory.wardCount -= 1;

console.log(teamInventory.wardCount); // 变成了 1！全队公用背包被扣减！
```

### 1.2 自动装箱（Autoboxing）：为什么原始字符串能调用 `.toUpperCase()`？
原始类型明明不是对象，为什么 `'invoker'.length` 可以工作？
- **物理机理**：当你在原始类型上调用方法时，引擎会在毫秒级瞬间创建一个**临时的包装对象（如 `new String('invoker')`）**，调用其原型方法，**方法调用完毕的瞬间立刻将临时包装对象当做垃圾销毁！**

## 第二战：隐式类型转换之神——`ToPrimitive` 算法

当把一个对象和一个基本类型进行加减比较时，引擎必须先将对象“打碎”成原始值，其仲裁顺序由 **`[Symbol.toPrimitive]` -> `valueOf()` -> `toString()`** 决定：

```javascript
const sacredRelic = {
  name: "圣者遗物",
  cost: 3800,
  
  // 现代 ES6 顶级仲裁器：优先度最高！
  [Symbol.toPrimitive](hint) {
    console.log(`[引擎发起 ToPrimitive 判定] 场景期望类型 hint: ${hint}`);
    if (hint === 'number') {
      return this.cost; // 数字运算时返回金币
    }
    if (hint === 'string') {
      return `【${this.name}】`;
    }
    return this.cost; // 默认 (default) 运算场景
  }
};

console.log(+sacredRelic);            // hint: 'number' -> 3800
console.log(`拥有装备: ${sacredRelic}`); // hint: 'string' -> "拥有装备: 【圣者遗物】"
console.log(sacredRelic + 200);       // hint: 'default' -> 4000
```

### 2.1 运算符暗黑转换潜规则：`+` 号的双重人格
- **加法 `+`**：只要有一侧是字符串（或者对象 `ToPrimitive` 后的结果是字符串），**全部降级为字符串拼接！**
  - `'5' + 3` -> `'53'`
  - `[] + {}` -> `"[object Object]"`
  - `[] + []` -> `""`
- **减号 `-` / 乘号 `*` / 除号 `/`**：完全不讲情面，**强制所有操作数调用 `ToNumber` 转换成数字！**
  - `'5' - 3` -> `2`
  - `'10' * '2'` -> `20`
  - `'5' - 'abc'` -> `NaN` (转换失败，判定为空刀)

## 第三战：真假眼判定——`==` vs `===` vs `Object.is`

### 3.1 宽松相等 `==` 的 12 步迷之算法
在对局中，尽量避免使用 `==`，因为它的隐式类型转换极其诡异：
1. 如果两边类型相同，走 `===`。
2. `null == undefined` 为 `true`，且它们与任何其他值比较都为 `false`。
3. `数字 == 字符串`：把字符串转为数字再比。
4. `布尔值 == 任何值`：**必须先把布尔值转为数字（`true -> 1, false -> 0`）再比！**
   - 经典天梯坑题：`'2' == true` 居然是 **`false`**！（因为 `true` 转为 `1`，变成 `'2' == 1`，再变成 `2 == 1`，结果为 `false`！）
5. `对象 == 原始类型`：对象调用 `ToPrimitive` 后再比。

### 3.2 终极天梯真理：`Object.is()` 对特异点的修复

`===` 绝大多数情况下是完美的，但在两个古老物理特异点上翻了车：
1. `NaN === NaN` 为 `false`（JavaScript 规定 NaN 不等于任何东西，包括它自己）。
2. `+0 === -0` 为 `true`（无法区分符号位物理方向）。

**`Object.is`（ES6 真实同值相等）彻底修复了这两个特异点：**

```javascript
// 1. NaN 判定
console.log(NaN === NaN);            // false (反人类)
console.log(Object.is(NaN, NaN));    // true (完美精准匹配！)

// 2. 正负零判定
console.log(+0 === -0);              // true (无法区分物理极性)
console.log(Object.is(+0, -0));      // false (精准识别电极反转！)
```

## 第四战：IEEE 754 浮点数精度危机（`0.1 + 0.2 !== 0.3`）

### 4.1 为什么会多出 `0.00000000000000004`？
JavaScript 中的 `Number` 遵循 **IEEE 754 双精度 64 位浮点数标准**：
- 1 位符号位（Sign）
- 11 位指数位（Exponent）
- 52 位尾数小数位（Mantissa）

在十进制中，`1/3` 是无限循环小数 `0.333333...`；  
而在二进制中，**十进制的 `0.1`（`0.0001100110011...`）和 `0.2` 同样是无限循环小数！**  
由于尾数位只能存 52 位，超出部分被直接截断舍入，导致最终加和结果变成了：  
`0.30000000000000004`！

```javascript
// ❌ 业余判定：团战残血判定直接失效！
function isFullHealth(hp) {
  return hp === 0.3; // 传入 0.1 + 0.2 时返回 false！直接被秒杀！
}

// ✅ 职业安全判定：借助机器精度极小值 Number.EPSILON
function areNumbersEqual(a, b) {
  return Math.abs(a - b) < Number.EPSILON;
}

console.log(areNumbersEqual(0.1 + 0.2, 0.3)); // true！安全穿透浮点误差！
```
