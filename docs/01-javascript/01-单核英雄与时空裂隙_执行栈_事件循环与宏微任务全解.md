## 战场核心世界观：为什么 JavaScript 是个“单核走单线”的英雄？

在 DOTA2 或 LOL 中，每一个玩家在同一时间点只能给英雄下发**一个物理指令**——你不可能在同一帧内既让卡尔在平 A，又让他在读条放大招。

这就是 **JavaScript 单线程（Single-Threaded）** 的宿命：
- **单个调用栈（One Call Stack）**：同一时刻，引擎只能干一件事。
- **不能被物理阻塞**：如果一个技能（比如向服务器发 HTTP 请求或者等待定时器）需要等 3 秒，若英雄这 3 秒停在原地发呆（主线程卡死），敌方防御塔和刺客早就把你秒了（浏览器直接弹出“页面未响应/崩溃”）。
- **破局神装**：**事件循环（Event Loop）+ 外部野区（Web APIs / 宿主环境多线程）**。英雄把耗时任务甩给野区野怪或信使去读条，自己继续在兵线上走砍补刀；读条完毕后，结果进入任务队列，等英雄手头连招打完（执行栈清空），再回首掏出技能收益！

## 第一战：执行栈（Call Stack）与技能连招（Stack Overflow）

### 1.1 技能压栈与出栈（LIFO：后进先出）
执行栈本质是一个**后进先出（Last-In-First-Out）**的数据结构。每当你的代码调用一个函数，JavaScript 就会为该函数创建一个**执行上下文（Execution Context）**并压入栈顶；函数返回后，立即从栈顶弹出。

```javascript
// 模拟盲僧的回旋踢连招
function flashR() {
  console.log("3. 闪现 + 猛龙摆尾！(栈顶执行完毕，准备弹出)");
}

function q2Follow() {
  console.log("2. 二段 Q 飞身突脸...");
  flashR(); // flashR 压入栈顶
  console.log("2. 二段 Q 后续判定完成 (弹出)");
}

function q1Cast() {
  console.log("1. 一段 Q 命中敌方 C 位...");
  q2Follow(); // q2Follow 压入栈顶
  console.log("1. 连招收尾 (弹出)");
}

q1Cast(); // 入口执行
```

**执行栈的物理流转过程**：
1. `q1Cast()` 入栈 -> 输出 `1. 一段 Q 命中`
2. `q2Follow()` 入栈 -> 输出 `2. 二段 Q 飞身`
3. `flashR()` 入栈 -> 输出 `3. 闪现 + 猛龙摆尾！`
4. `flashR()` 返回 -> 出栈
5. `q2Follow()` 继续输出 `2. 后续判定完成` -> 出栈
6. `q1Cast()` 继续输出 `1. 连招收尾` -> 出栈，主栈归空！

### 1.2 贪心无限连招导致暴毙：爆栈（Stack Overflow）
如果你的英雄陷入了死循环递归，没有设计退出判定（递归基基准条件），执行栈空间会被瞬间挤爆，直接抛出 `RangeError: Maximum call stack size exceeded`：

```javascript
// 致命的死递归连招
function infiniteCombo() {
  return infiniteCombo(); // 没有技能终止条件，无限压栈！
}

// infiniteCombo(); // 💥 触发浏览器保护机制，主线程暴毙断开连接！
```

**实战防御神装（尾调用优化或蹦床函数 Trampoline）**：
```javascript
// 蹦床函数：利用循环将压栈化解为平级轮询，彻底免疫爆栈
function trampoline(fn) {
  return function(...args) {
    let result = fn(...args);
    while (typeof result === 'function') {
      result = result(); // 每次执行完立即释放上一层栈，绝不堆叠！
    }
    return result;
  };
}

function safeSum(n, acc = 0) {
  if (n <= 0) return acc;
  return () => safeSum(n - 1, acc + n); // 返回函数闭包而非直接递归
}

const runSafeSum = trampoline(safeSum);
console.log(runSafeSum(100000)); // 轻松扛住 10 万次运算，栈深度始终为 1！
```

## 第二战：事件循环（Event Loop）核心机制与任务分级

### 2.1 宏任务（Macrotasks）vs 微任务（Microtasks）的等级森严

在天梯比赛中，战况指令是有严格优先级的：
- **微任务（Microtasks，特权级插队指令）**：
  - 代表 API：`Promise.then/catch/finally`、`queueMicrotask()`、`MutationObserver`（Node.js 中的 `process.nextTick`）。
  - **特权规则**：**只要微任务队列里还有指令，事件循环就绝不会进入下一轮宏任务！必须一口气全部清空！** 就像敌方在拆基地，你必须立即打完所有微操作，不能中途去商店买装备。
- **宏任务（Macrotasks，常规任务）**：
  - 代表 API：`setTimeout`、`setInterval`、`setImmediate` (Node.js)、I/O 操作、UI 交互事件。
  - **排队规则**：**每一轮事件循环只取一个宏任务！** 执行完毕后，立刻检查并清空微任务队列，再决定是否渲染，然后再取下一个宏任务。

### 2.2 经典天梯连招时序实战拆解

请看这段让无数初级召唤师翻车的时序代码：

```javascript
console.log('1. 泉水出门平 A (同步任务)');

setTimeout(() => {
  console.log('5. 定时炸弹爆炸 (宏任务 Macrotask)');
}, 0);

Promise.resolve()
  .then(() => {
    console.log('3. 饮血剑被动吸血 (微任务 1 Microtask)');
  })
  .then(() => {
    console.log('4. 征服者叠满 12 层 (微任务 2 Microtask)');
  });

console.log('2. 闪现过墙 (同步任务)');

// 控制台真实输出顺序：
// 1. 泉水出门平 A (同步任务)
// 2. 闪现过墙 (同步任务)
// 3. 饮血剑被动吸血 (微任务 1 Microtask)
// 4. 征服者叠满 12 层 (微任务 2 Microtask)
// 5. 定时炸弹爆炸 (宏任务 Macrotask)
```

**为什么 `setTimeout(..., 0)` 哪怕是 0 毫秒也必定在 `Promise` 之后？**
1. 执行栈先同步执行 `console.log('1')` 和 `console.log('2')`。
2. `setTimeout` 将其回调扔给浏览器计时器，0ms 到期后放入 **宏任务队列（Macrotask Queue）**。
3. `Promise.then` 将其回调放入 **微任务队列（Microtask Queue）**。
4. 同步代码执行完毕，执行栈清空。
5. **事件循环裁判登场**：首先审查微任务队列！发现微任务 1，执行之；微任务 1 又产生了微任务 2，**继续执行微任务 2 直到微任务队列彻底见底！**
6. 微任务全部清空后，事件循环才移步宏任务队列，拿出 `setTimeout` 的回调执行！

```
======================================================================
事件循环黄金轮转定律：
[同步执行栈清空] ──> [清空全部微任务] ──> [检查更新 UI 渲染] ──> [取下一个宏任务]
        ▲                                                      │
        └──────────────────────────────────────────────────────┘
======================================================================
```

## 第三战：锁帧神器 `requestAnimationFrame`（rAF）

### 3.1 为什么不要用 `setInterval` 搞技能动画？
屏幕刷新率通常是 60Hz（每 16.6ms 一帧）或 144Hz（每 6.94ms 一帧）。
- `setInterval(..., 16)` 是**盲目计时器**。如果它触发时浏览器正好在忙着渲染重绘，或者当前帧还没结束，就会发生**丢帧（Jank / 掉帧卡顿）**。
- `requestAnimationFrame(callback)` 是**官方垂直同步锁帧器**：它保证你的回调**恰好在浏览器下一次重绘绘制屏幕之前精确执行一次**！

```javascript
// 模拟 144Hz 极限丝滑英雄平移走砍
let heroPositionX = 0;

function smoothStep(timestamp) {
  heroPositionX += 5; // 每帧向前移动 5 像素
  const heroElement = document.getElementById('hero');
  if (heroElement) {
    heroElement.style.transform = `translateX(${heroPositionX}px)`;
  }
  
  if (heroPositionX < 500) {
    // 递归向下一帧预约，与显示器刷新硬件严格同步！
    requestAnimationFrame(smoothStep);
  }
}

// 启动走砍动画
requestAnimationFrame(smoothStep);
```

### 3.2 微任务、宏任务与 rAF 的完整时序对照表

| 任务类型 | 代表 API | 触发执行时机 | 典型场景 |
| :--- | :--- | :--- | :--- |
| **同步代码** | 赋值、`for` 循环、常规函数 | 立即占用执行栈执行 | 英雄当前攻击判定 |
| **微任务 (Microtask)** | `Promise.then`、`queueMicrotask` | 执行栈空后**立即插队，全部扫空** | 状态更新闭环、数据事务提交 |
| **帧前绘制 (rAF)** | `requestAnimationFrame` | 每一帧**渲染树重排（Reflow）与绘制（Repaint）之前** | 丝滑位移、视觉补间动画 |
| **宏任务 (Macrotask)** | `setTimeout`、`setInterval`、I/O | 每一轮事件循环只执行**一个** | 长轮询、防抖重置、延时动作 |

## 第四战：对线后摇取消——防抖（Debounce）与节流（Throttle）

高段位玩家都懂：平 A 后的动作后摇必须取消，而狂按技能键不能导致多余的技能空放。在前端业务中，疯狂滚轮、窗口缩放或频繁输入搜索框，如果不加控制，会高频轰炸主线程引发卡顿。

### 4.1 防抖（Debounce）：回城打断机制（只认最后一次）
- **机制**：你按了 B 键回城，需要读条 8 秒。如果在第 7 秒你又动了一下，**读条立刻打断重置，重新从 0 秒开始算！** 只有当你彻底停止操作达到指定时间后，动作才最终生效。
- **实战手写（带立即执行与取消能力）**：

```javascript
/**
 * 英雄回城防抖函数
 * @param {Function} fn 真正要触发的大招/搜索请求
 * @param {number} delay 读条静止时间 (ms)
 * @param {boolean} immediate 是否开局立刻抢先打一下
 */
function debounce(fn, delay, immediate = false) {
  let timer = null;

  function debounced(...args) {
    const context = this;
    if (timer) clearTimeout(timer); // 只要乱动，立刻取消上次的读条！

    if (immediate) {
      const callNow = !timer;
      timer = setTimeout(() => {
        timer = null; // 冷却结束，允许下次再立即触发
      }, delay);
      if (callNow) fn.apply(context, args);
    } else {
      timer = setTimeout(() => {
        fn.apply(context, args);
      }, delay);
    }
  }

  // 辅助技能：手动打断回城
  debounced.cancel = function() {
    if (timer) {
      clearTimeout(timer);
      timer = null;
    }
  };

  return debounced;
}

// 模拟英雄在草丛反复按技能，只有停手 300ms 后才发包
const onInputSearch = debounce((query) => {
  console.log("向服务器侦察兵发包搜索:", query);
}, 300);
```

### 4.2 节流（Throttle）：技能 CD 冷却锁（固定频率触发）
- **机制**：英雄普通攻击有攻速限制（例如 1 秒只能砍 1 刀）。无论你这 1 秒内右键狂点了鼠标 100 次，英雄也**只能在冷却时间到了的时候砍出那一刀**。
- **实战手写（时间戳 + 定时器双保底版本，首尾兼顾）**：

```javascript
/**
 * 技能 CD 节流函数（高精双保底）
 * @param {Function} fn 技能触发函数
 * @param {number} limit 冷却时间 (ms)
 */
function throttle(fn, limit) {
  let lastTime = 0;
  let timer = null;

  return function(...args) {
    const context = this;
    const now = Date.now();
    const remaining = limit - (now - lastTime);

    // 冷却已转好，或者系统时钟被篡改
    if (remaining <= 0 || remaining > limit) {
      if (timer) {
        clearTimeout(timer);
        timer = null;
      }
      lastTime = now;
      fn.apply(context, args);
    } else if (!timer) {
      // 保证技能在最后一次按键冷却结束后，还能补刀一次（Trailing 触发）
      timer = setTimeout(() => {
        lastTime = Date.now();
        timer = null;
        fn.apply(context, args);
      }, remaining);
    }
  };
}

// 页面滚动事件监听：每 200ms 严格触发一次视野检查，绝不多占一帧算力！
window.addEventListener('scroll', throttle(() => {
  console.log("视野侦测：更新战争迷雾野怪状态");
}, 200));
```
