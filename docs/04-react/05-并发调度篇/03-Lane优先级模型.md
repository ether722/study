# Lane 赛道模型：31 条兵线优先级与全图位运算调度

> 核心战法: 告别粗糙的时间戳，拥抱 31 条专业电竞兵线！  
> 位运算兵法: 按位与抢龙、按位或合流、lowbit 瞬间锁定头号军情！

---

在上一回我们知道，`Scheduler`（调度器）与 `React` 内部有一套极为精密的优先级管控体系。
在召唤师峡谷中，存在多种截然不同紧急程度的战况：

1. **保命大招 / BKB 闪现（同步极高优）**：比如用户敲键盘输入、按了退出 Esc，一刻都不能等，必须立刻交技能！
2. **走位与鼠标拖拽（高优持续交互）**：比如持续走 A、拉扯小兵，必须顺滑跟手。
3. **网络回包（普通平 A 补刀）**：后端接口数据回来了，按部就班刷新列表。
4. **探视野 / 打野怪（低优 Transition）**：大视图切换、Suspense 假动作，不急，可以慢慢加载。

React 必须打造一套数学模型，同时满足三大严苛军规：
- **精准区分高下**（闪现优先级必须碾压打野）；
- **支持兵线批处理（Batching）**（多路大军可以抱团一起推塔）；
- **极速性能计算**（必须在单条 CPU 指令周期内算完优先级决策）。

为此，React 设计了震古烁今的 **Lane（赛车道 / 兵线）模型**！

## 🏎️ 一、31 位的二进制兵线大盘点

想象你身处 F1 赛车场或一张 31 路兵线的巨型 MOBA 地图：
内圈赛道最短（优先级最高），外圈赛道最长（优先级较低）。

React 借鉴了这个概念，使用 **32 位整型中的 31 位二进制数**，代表 **31 条全图赛道**：
**位数越小（越靠近右侧末尾），优先级越高！**

```ts
export const NoLanes: Lanes = /*                        */ 0b0000000000000000000000000000000; // 零军情
export const NoLane: Lane = /*                          */ 0b0000000000000000000000000000000;

// 【第 1 兵线】：最高危！保命闪现/BKB，同步无条件立刻执行！
export const SyncLane: Lane = /*                        */ 0b0000000000000000000000000000001; 
export const SyncBatchedLane: Lane = /*                 */ 0b0000000000000000000000000000010;

// 【第 3~4 兵线】：用户独立离散交互（点击、按键）
export const InputDiscreteHydrationLane: Lane = /*      */ 0b0000000000000000000000000000100;
const InputDiscreteLanes: Lanes = /*                    */ 0b0000000000000000000000000011000;

// 【第 5~7 兵线】：用户连续平滑交互（鼠标拖拽、页面滚动走位）
const InputContinuousHydrationLane: Lane = /*           */ 0b0000000000000000000000000100000;
const InputContinuousLanes: Lanes = /*                  */ 0b0000000000000000000000011000000;

// 【第 8~10 兵线】：普通日常任务（接口网络回包、正常补刀更新）
export const DefaultHydrationLane: Lane = /*            */ 0b0000000000000000000000100000000;
export const DefaultLanes: Lanes = /*                   */ 0b0000000000000000000111000000000;

// 【第 11~19 兵线】：转场过渡任务（useTransition, Suspense, 切大Tab打野）
const TransitionHydrationLane: Lane = /*                */ 0b0000000000000000001000000000000;
const TransitionLanes: Lanes = /*                       */ 0b0000000001111111110000000000000;

// 【第 20~23 兵线】：重试兵线
const RetryLanes: Lanes = /*                            */ 0b0000011110000000000000000000000;

// 【第 28~30 兵线】：挂机空闲任务（Idle）
const IdleLanes: Lanes = /*                             */ 0b0110000000000000000000000000000;

// 【第 31 兵线】：离屏隐藏（Offscreen）
export const OffscreenLane: Lane = /*                   */ 0b1000000000000000000000000000000;
```

## 👥 二、单兵（Lane）与军团（Lanes）：“批处理”的战术玄机

注意源码中的单复数：
- `Lane`（单数）：指代**单一一根车道**（只有一个二进制位是 1）；
- `Lanes`（复数）：指代**包含多条车道的混合大军**（有多个二进制位是 1）。

### 细思极恐的细节：为什么低优先级任务占用的二进制位特别多？
看上面的代码：
- `SyncLane`（闪现）：**只占了 1 个位**；
- `DefaultLanes`（补刀）：占了 **3 个位**；
- `TransitionLanes`（打野）：**一口气狂占了 9 个位**！

**为什么越垃圾的任务，反而占的地盘越多？**
> **因为低优任务随时会被高优大招打断！**  
> 闪现一开瞬间完成，根本不需要排队积压；而打野任务（Transition）天天被插队打断，很容易在队列里堆积七八个未完成的过渡请求。  
> 必须给它分配 9 个槽位，允许不同子任务同时在这些车道上并行挂起，防止单车道被彻底占满塞车！

## ⚡ 三、汇编级战术位运算：纳秒级决策指挥

既然把赛道映射成了二进制位，那么战术推演就全变成了**单指令周期的位运算神技**！

### 1. 探查两路大军是否有冲突（按位与 `&`）
想知道战术 A 和战术 B 是否看中了同一条兵线：
```ts
export function includesSomeLane(a: Lanes | Lane, b: Lanes | Lane) {
  return (a & b) !== NoLanes; // 只要结果不为0，说明撞车了！
}
```

### 2. 多路兵线合并大进军（按位或 `|`）
把点击任务、数据请求任务打包成一个批次一起处理：
```ts
export function mergeLanes(a: Lanes | Lane, b: Lanes | Lane): Lanes {
  return a | b; // 一键合兵！
}
```

### 3. 清理已拔除的兵线（按位非与按位与 `& ~`）
任务完成后，把这条车道从当前调度集合中抹除：
```ts
export function removeLanes(set: Lanes, subset: Lanes | Lane): Lanes {
  return set & ~subset; // 战利品收割清场！
}
```

### 4. 终极神技：提取全场最紧迫的带头大哥（lowbit 算法）
当手里拿着一堆混合兵线 `lanes = 0b01011000` 时，如何瞬间找出那个优先级最高的带头大哥？
```ts
export function getHighestPriorityLane(lanes: Lanes): Lane {
  return lanes & -lanes; // 绝杀！CPU 级 lowbit 提取最右边的首个 1！
}
```
这一行代码，直接利用了计算机负数补码的特性，一条 CPU 汇编指令瞬间锁定最高危任务，无需任何 `for` 循环遍历数组！

## 🏆 四、本回总结与战术通报

1. **31 条兵线**：使用 31 位二进制精准区分任务紧急程度，右侧为高危保命，左侧为休闲打野；
2. **批处理缓冲**：越低优的任务分配越多的二进制位，给积压和打断留足退路；
