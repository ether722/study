# Hooks 理念：从笨重机甲到原生超能英雄的降维打击

> 进化史诗: 为什么说类组件是傻大黑粗的笨重机甲，而 Hooks 才是高机动性超能英雄？  
> 核心心智: 别再用类组件生命周期去生搬硬套 Hooks，这是两个不同维度的对线战法！

---

注意：在开始本节之前，假设你已经熟练掌握了在排位中按 QWER 施放各类 Hooks 的基本操作。

很多选手在日常对局中，只把 Hooks 当成类组件（`ClassComponent`）的平替语法糖。但作为一个要通透源码的职业战队架构师，我们必须跳出普通玩家视角，以**游戏数值主策划**的视角来看看：Hooks 到底是凭什么颠覆整个战局的？

---

## ⚛️ 一、从战队队标 LOGO 聊起：原子与游离电子

看一下 React 官方战队的 LOGO 标志：
那是一个代表 **原子（Atom）** 的经典物理符号。世间万物由原子组成，原子的类型决定了装备和战甲的形态。

在老时代，我们把 `ClassComponent`（类组件）看作一个个不可分割的“战斗机甲”：
- 这个机甲身上焊接了各种沉重的外挂系统：`this` 绑定、厚重的生命周期钩子（`componentDidMount`、`componentWillUpdate`）；
- 表面上看功能齐全，但在高频快节奏的团战走 A 中，这种机甲笨重得让人窒息！

而 **Hooks** 的出现，就像科学家打破了原子、发现了更底层的 **电子（Electron）**：
- 它不再是沉重的整机装甲，而是**直接操控底层粒子风暴的超能英雄**！
- 它与 React 世界最底层的物理定律（`schedule - render - commit` 运行管线）贴合得更加丝滑纯粹！

---

## 🚫 二、致命误区：别再拿类组件的生命周期来硬套 Hooks！

很多老玩家在转职 Hooks 时，教练和前辈总喜欢这么教：
> “哎呀，`useEffect(fn, [])` 就相当于 `componentDidMount` 嘛！`useEffect(fn, [val])` 就相当于 `componentDidUpdate` 嘛！”

这种类比对于新手打人机对线确实容易上手，但一旦进入高强度职业局，**你的战术心智就会彻底精神分裂！**

### 经典翻车案例：谁能代替 `componentWillReceiveProps`？
有人张口就来：“那肯定是带依赖项的 `useEffect` 啊！”
```js
useEffect(() => {
  console.log('技能参数变了！');
}, [props.spellId]);
```

**大错特错！这俩根本不是一个时空的产物！**
- `componentWillReceiveProps` 是在 **Render 阶段**（内存推演时）同步触发的；
- 而 `useEffect` 是在 **Commit 阶段页面已经全部画完之后**，异步延迟执行的！
- 这就像你以为你在“出招前摇”阶段打出了闪现，实际上你的大招是在“敌方水晶爆炸后”才结算出来的！两者执行时差差了整整一个维度！

---

## ⚡ 三、为什么说 Hooks 是并发模式（Concurrent Mode）的天命搭档？

`Concurrent Mode`（并发走 A 模式）是 React 未来的统治战法。
在并发模式下：
- **Render 阶段的推演随时可能被敌方大招打断！**
- 如果你用老机甲的类组件，组件推演被打断后，那些写在 `componentWillXXX` 里的副作用代码就会被反复触发，直接引发灾难性的幽灵技能 Bug！
- 而 Hooks 彻底将状态（`useState`）、数据订阅（`useEffect`）与纯函数渲染进行解耦，天生自带“纯函数重复执行无害”的纯净体质！

正如 React 核心主策划 Dan 在全球峰会演讲结尾所说：
> “你凝视 React LOGO 时，那些环绕在核心外围的电子飞行轨道 —— Hooks 或许自始至终就在那里，等待着超能英雄的觉醒。”
