## 🎯 一、优先级的评级军规：以选手心智为准

状态更新是由选手操作触发的。选手的潜意识里对各种事件有着极度严格的心理优先级预期：

1. **绝对同步执行（不可逾越）**：生命周期方法、受控的文本输入（选手正在狂按技能打字，哪怕慢 1ms 就会摔键盘骂街）；
2. **高优先级执行（动作位移）**：动画播放、鼠标拖拽、技能弹道追踪；
3. **普通/低优先级执行（打野探视野）**：异步数据请求、接口拉取、日志上报。

## 🛑 二、经典战况推演：高危技能（闪现）强行插队打断！

看下面这个真实对局：
- 战术指令 1（`u1`）：玩家点击“切换夜间暗黑模式”（运算量巨大，低优打野任务）；
- 战术指令 2（`u2`）：玩家突然在搜索框输入了一个字母 `'I'`（高危闪现级任务，必须秒回）。

```
【第一幕：u1 正在慢吞吞清野】
fiber.updateQueue = {
  baseState: { blackTheme: true, text: 'H' },
  shared: { pending: u1 }
};
```
参谋部正在慢吞吞推演 `u1`。推演刚走到一半，突然键盘敲下 `'I'` 产生了 `u2`！
`u2` 带有极高的紧急位（Lane），调度官立刻大喊：
> **“前线紧急求援！暂停 u1 施工，全军立刻给 u2 让路！”**

此时 `u2` 霸气插入环状链表：
```
shared.pending === u2 ──► u1 ──► u2 (首尾相连环状队列)
```

### 第二幕：u2 强行插队，u1 委屈靠边
进入 `u2` 的紧急渲染阶段：
1. 参谋部解开环状链表，顺序是 `u1 ──► u2`；
2. 检查优先级：`u1` 优先级太低，**本次团战直接跳过不执行！**
3. 优先执行高危的 `u2`，将文字立即变成 `'HI'`，并以光速推上屏幕给选手交差！
4. **但核心细节来了**：被跳过的 `u1` 会被丢弃吗？
   **绝对不会！被跳过的 `u1` 及其后面的所有技能，全部留存在 `baseUpdate` 战备储备库中！**

```
fiber.updateQueue = {
  baseState: { blackTheme: true, text: 'HI' },
  firstBaseUpdate: u1,
  lastBaseUpdate: u2
};
```

### 第三幕：打扫战场，回头重刷 u1（最终状态完全闭环）
当高优的 `u2` 上屏后，主线程空闲下来了，调度官下令：**“危机解除，开始回补刚才被跳过的 u1！”**
- 基于 `firstBaseUpdate` 重新启动一次 Render 推演；
- 这一次，`u1` 和 `u2` 会按顺序完整重新结算一遍；
- 最终结果：暗黑模式成功切换（`blackTheme: false`），文字依然是最新状态（`text: 'HI'`）！

**战况惊魂真相**：
因为 `u2` 被执行了整整两次，所以在类组件中，处于 Render 阶段的老生命周期钩子（如 `componentWillMount` / `componentWillUpdate`）**会被迫触发两次！**
**这就是为什么 React 官方痛下杀手，将这些老钩子全面标记为 `UNSAFE_` 并彻底废弃的根本死因！**

## 🔒 三、如何保证团战状态绝对不丢？（状态依赖的连续性）

很多指挥官会有个巨大疑问：
> “如果任务 A 是低优（HP + 10），任务 B 是高优（HP 乘以 2）。先跳过 A 执行 B，算完 B 再回头算 A，状态不会算错乱套吗？！”

看下面这组战术序列：
```
baseState: ''
更新队列: A1 ──► B2 ──► C1 ──► D2
(字母为动作，数字为优先级，1 为高危闪现，2 为低优打野)
```

### 第一次交锋（只打高优 1 级战场）：
- 遇到 `A1`：优先级够高，执行！当前状态变为 `"A"`；
- 遇到 `B2`：优先级太低，跳过！
- **🚨 核心军规：一旦某个任务被跳过，它后面的所有任务（无论优先级多高）全都要在备用仓库里重新排队！**
- 遇到 `C1`：执行！最终当前屏幕状态变为 `"AC"`；
- 此时留下备用的备份队列：`B2 ──► C1 ──► D2`，备份基底 `baseState: "A"`。

### 第二次交锋（回补 2 级战场）：
- 从 `baseState: "A"` 开始，依次完整执行备份队列 `B2 ──► C1 ──► D2`；
- 最终状态：`"ABCD"`！

**战术结论：**
React 宁可在中间某一瞬先展示高优结果（让选手按键走位不卡），但它通过严格的链表前驱回溯，**在最终时刻 100% 保证战果绝对不出现逻辑偏差！**

## 🏆 四、本回总结与战术通报

1. **高优插队机制**：用户输入具有极高特权，可以随时打断慢速渲染并率先上屏；
2. **`UNSAFE_` 勾子死因**：被打断的高优任务会反复触发 Render 阶段生命周期；
3. **连续性保证**：被跳过的更新会协同后续所有更新一起打入 `baseUpdate` 待命库，保障最终状态分毫不差。
